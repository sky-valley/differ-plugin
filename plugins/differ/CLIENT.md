# Publishing contract

The local bridge exposes publisher_status, check_content, publish_directory,
publication_status, get_bit, connect_account, connection_status and
disconnect_account, plus optional media helpers. It transfers local asset bytes
without making the model transcribe them. Copied player prompts retain their
reserved bit and upload pass; do not replace them with a fresh plugin publication.

Control is the publisher. The helper addresses https://publish.getdiffer.com, or
DIFFER_PUBLISH_URL (HTTPS, or loopback HTTP for a local Control); saved
configuration never chooses it. Publishing errors are {code, message}; OAuth
errors are {error, error_description}. The helper reports both as code and
message and adds its own recovery.

## Bits, versions and captions

A bit is one piece of content and all its versions; a version is one immutable
upload of it. The caption is the maker's own words shown over the bit: 1–200
characters after trimming, at most 800 bytes, no control characters but line
breaks and at most 3 of those. An upload's caption is optional, a suggestion the
maker confirms in Differ before the bit goes public; the helper sends one only
when given --caption (tool input caption) or when differ-bit.json saved one for
the same bit. A new bit (--new) and a diff start with none: a diff never copies
its parent's words. The bit's title is generated by Differ from its current
version and is never sent.

## Guest and connected publishing

A guest bit starts with POST /v1/publishing/bits/{id}/reservation
{ownerProof}: a fresh UUID and 64 lowercase hex characters, saved before the
request so a lost response is recovered by reserving again. Control stores
hashes and derives the upload pass from the proof. Its 201 reservation returns
the pass, the private claim link and the deadline. The helper keeps the link in
its private journal and shows it; it never builds one.

POST /v1/publishing/bits/{id}/versions carries Authorization: Bearer with the
guest upload pass or the connected account's access token. The body is
{requestId, caption (optional), expectedVersionId (null first), files [{path,
base64 content}]}, plus parentBitId and parentVersionId for a diff. The bit id
and credentials never travel in it. A connected account creates a bit by
publishing to a fresh UUID and adds versions only to bits it owns. GET
/v1/publishing/bits/{id}/operations/{requestId} with the same bearer returns
the saved receipt, or state unknown: retry the exact saved request.

Same request/payload returns the saved upload receipt; changed content
conflicts (request_conflict), and so does a stale expectedVersionId
(version_conflict). Control stores each file once by SHA-256, then saves a
complete manifest and a draft or published version. A 4xx refuses a request
before anything commits, so the helper drops it. reconnect_required and
upload_busy can follow an earlier attempt that did commit; those, network
failures and 5xx keep the request for status and an exact retry.

A receipt is {state, requestId, bitId, versionId, artifactId, runtimeUrl, url,
claimed, expiresAt, draft}; the helper shows its `url`, the bit's page.
Unclaimed receipts include the deadline. Connected helper uploads instead
return `draft: true`, a draft `url` where the maker previews it, confirms its
caption and publishes it, the `versionId` it becomes, and an expiry, with no
runtime URL. The next upload names that pending version as `expectedVersionId`.
The helper reports drafts as unpublished and skips public-content
verification. It does not send `publish: true`; the human publishes from the
returned draft page. The remote connector supports that flag when explicitly
asked to skip preview. artifactId is the lowercase SHA-256 of compact UTF-8
JSON `{"files":{"path":"sha256 of file bytes"}}`, with paths sorted lexically.
The helper computes that same manifest digest to recognize unchanged content.

## Bundles and preview

A bundle is static files with a root index.html, the bit as it opens: laid out
at 390×693 CSS pixels for checking and responsive on every phone. A root
preview.html is optional: the 390×520 interactive preview the feed shows. check
warns when it is missing, because the feed then shows index.html scaled into
that box. Differ reserves the paths __differ/, __dfr/, -/, v/ and uploads/;
check refuses files under them and any reference to /__differ/ or /__dfr/. Differ adds its
SDK, /__differ/sdk.js, to every page of a bit itself.

preview serves the bundle on loopback with a stand-in for that SDK at the head
of every page a browser opens or frames, and a player page at /__differ/ that
frames preview.html at 390×520 and index.html at 390×693. It follows the
player protocol: a frame hears nothing before its differ:ready, then
differ:show, and the open index.html then hears differ:open with the state a
preview opened it with, or null. Presses on the preview are forwarded as
differ:pointer; a vertical drag is the feed's and cancels the gesture.
differ:open counts only from preview.html within a second of a tap, and
differ:close only from index.html, which closes it. Open and close are logged
on the page and in the console. Stateful bundles (rules.html) need a runtime
preview instead.

## Claims and ownership

GET /v1/publishing/bits/{id} is public: {id, ready, claimed, expiresAt, url,
bit}; bit names its owner's handle only once claimed. No public binding, bit,
feed, runtime or URL grants ownership. Opening the claim link claims nothing;
the player's verified sign-in binds the bit to that person's handle with the
caption they confirm, keeps every bit and version ID and ends the guest pass.
Later guest versions are refused (owner_conflict); an exact earlier request
still returns its receipt.

A connected account is its handle: GET /v1/publishing/account returns
{handle}. The helper uploads a guest bit's next version as the account once the
bit is claimed under that handle, and stops before upload when another creator
owns it. Connecting claims nothing: unclaimed guest bits keep using their pass.

## Connections

The stdio bridge uses the OAuth device flow for deliberate browser approval:
POST /oauth/device (client_id differ-plugin, resource <publisher>/mcp, scope
"profile bits:write"), POST /oauth/token with the device_code grant and then
refresh_token grants, and POST /oauth/revoke on disconnect. Tokens are opaque;
access lasts 15 minutes and a connection 30 days. Refresh tokens rotate and a
replayed one revokes the connection. Concurrent refresh is serialized locally.

The private mode-600 config holds {url, mode, accessToken, refreshToken,
expiresAt, accountHandle}. No tokens appear in receipts or normal tool output.
A token Control refuses (401 reconnect_required) stops publishing; the helper
never falls back to guest. A connection saved for another publisher fails with
target_changed: run connect. Disconnect revokes the grant before selecting
guest mode. The player /connect page can revoke other connections.

Remote MCP at <publisher>/mcp offers get_profile, start_bit, publish_bit,
get_bit, publish_as_me and start_upload_as_me, whose inputs name caption,
expectedVersionId, parentBitId and parentVersionId. Guest tools use bounded
per-bit capabilities. Protected tools advertise OAuth scopes and return MCP
authorization challenges. Discovery uses RFC 9728 and OAuth
authorization-server metadata, exact registered redirects, authorization code +
S256 PKCE, resource validation, and revocation. Dynamic client registration is
supported for current host interoperability; client metadata documents (CIMD)
are not yet supported. Production host acceptance still needs testing in each
host; this is not a claim of App Directory approval or mobile file access.

## Durable local state

Keep differ-bit.json with source: {version: 1, publisher, bitId, versionId,
caption}, the caption being the words that version was uploaded with ("" when
none). This public binding is excluded from uploads and does not grant editing
permission. Keep .differ/state.json private: it contains the guest proof,
upload pass and claim link, requests, receipts and earlier bits' handoffs when
intentionally starting new bits. Never delete uncertain pending state.
Destination and account changes stop; bind is deliberate conflict recovery after
reviewing the current version. Bindings and journals made for another publisher
stop with target_changed.

A differ-post.json or a .differ journal from a helper before 0.7.0 stops every
command (stale_binding, stale_state) and is never read or uploaded: remove it,
keeping any claim link it holds, then bind DIR --bit ID or publish with --new.
Unsupported saved configurations fail closed instead of silently changing
identity.
